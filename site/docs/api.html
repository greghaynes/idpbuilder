API Reference

IDP Builder provides several Custom Resource Definitions (CRDs) that allow you to declaratively manage your internal developer platform on Kubernetes.

📖 About This Documentation

This API reference is automatically generated from the Go source code using standard Kubernetes tooling (crd-ref-docs). It provides detailed information about all fields, types, and validation rules for each Custom Resource.

API Versions

IDP Builder provides two API versions:

v1alpha1

Status: Deprecated (transitioning to v1alpha2)

The original API version with monolithic resources. Includes:

  • Localbuild - Legacy all-in-one resource
  • CustomPackage - Package management
  • GitRepository - Git repository management

v1alpha2

Status: Current (recommended)

The new modular architecture with pluggable providers. Includes:

  • Platform - Main platform orchestration resource
  • GiteaProvider - In-cluster Git server provider
  • NginxGateway - Nginx Ingress gateway provider
  • ArgoCDProvider - ArgoCD GitOps provider

Custom Resources

Platform (v1alpha2)

The Platform resource is the main entry point for defining your IDP. It orchestrates multiple providers and manages the overall platform lifecycle.

Key Features:

  • References multiple provider types (Git, Gateway, GitOps)
  • Manages platform-wide configuration
  • Provides status information about component health

View detailed Platform API reference →

Provider Resources (v1alpha2)

Provider resources represent specific platform components that can be plugged into a Platform:

GiteaProvider

Deploys and manages an in-cluster Gitea Git server with automatic configuration for repositories, organizations, and users.

View GiteaProvider reference →

NginxGateway

Deploys and configures Nginx Ingress Controller for routing traffic to platform components.

View NginxGateway reference →

ArgoCDProvider

Deploys and configures ArgoCD for GitOps-based application deployment and management.

View ArgoCDProvider reference →

Using the API

You can create these resources in two ways:

1. Using the CLI (Development Mode)

The CLI automatically creates appropriate resources based on your requirements:

idpbuilder create

2. Declaratively via kubectl (Production Mode)

Create resources directly in your Kubernetes cluster:

kubectl apply -f platform.yaml
